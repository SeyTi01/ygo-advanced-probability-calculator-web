# Delegation

Delegate when task size, context volume, separable work or independent verification justifies coordination. The lead owns architecture, integration and final judgment; delegate bounded supporting work rather than appointing another lead.

Choose from models/reasoning levels actually available. Use economical configurations for mechanical work and stronger ones when ambiguity or consequences warrant them. Do not claim unavailable configurations.

Give each agent its assignment from the current plan, source paths, relevant decisions/contracts, dependencies, acceptance criteria and expected output. Pass only needed context; use full history only when necessary. Do not make agents rediscover settled decisions or repeat valid checks.

Before parallel edits, assign non-overlapping file ownership and identify read-only files. One owner coordinates shared-file edits. Agents report a needed boundary change before crossing it; dependent work proceeds sequentially.

Investigators return concise findings with exact sources, evidence and unresolved questions. Implementers return changed paths, behavior, checks actually performed and remaining limits. The lead reviews consequential source, assumptions, edge cases and edits directly before integrating and updates the current task record.
