# One selected mechanism (fixed before candidate runs)

Baseline diagnosis: representative count-state total widths 4.17--11.99 pp;
Exact lies near their upper endpoints. VS/K9: L=85.91439158%, P=89.93131137%,
U=90.08564045%. Thus a necessary survival upper proof cannot address most width.
Ordered/deferred controls reach Exact Work limits (150m) after splitting inert
fillers; retain their original Fast bounds and decline this prototype.

Choose disjoint physical count-state terminal regions, descending probability mass.
Reuse existing SearchAccessPlan, Hall/compiled events, decision diagram and joint
SurvivorCounter; union predicates before weighting. No card-specific formulas.
For completed disjoint regions R, S=sum P(R)*P(success|R), M=sum P(R).
Every row has certified S <= P(success) <= S+1-M. Intersect with the old interval.
Each group/total has its own Boolean-union predicate on the same sample space.
Unfinished region contributes no success or failure proof. Commit checkpoints only
after all rows and retained diagnostic storage checks complete. A failed child
retains the preceding checkpoint, or old certificate if none completed.

The Fast distribution merges observed-source counts, so this offline prototype
rebuilds the physical distribution with the existing resolver. This is charged,
and is a limitation of reuse. It duplicates Exact's region work; it does not claim
an independently cheaper counter. The test is whether early bounded region
completion yields useful precision before most Exact work is paid.
Eligibility: completed bounded SearchCountState request only. Other routes and
already-exact inputs decline. Additional budgets remain 100k/1m as predeclared.
Full primary and public baseline result are retained byte-for-byte; hypothetical
endpoints are separate diagnostics. Exact never invokes refinement.
No design revision after held-out results. Stop if this misses precision/economic gates.
